# Globe data sources

Static files used by the 3D globe (`src/components/EarthGlobe.tsx`).

## Borders: Natural Earth (public domain)

- Source: https://github.com/nvkelso/natural-earth-vector, commit `ca96624a56bd078437bca8184e78163e5039ad19`
  - `geojson/ne_50m_admin_0_countries.geojson` (countries, 1:50m)
  - `geojson/ne_10m_admin_1_states_provinces.geojson` (first-order administrative regions, 1:10m)
- Terms: public domain, https://www.naturalearthdata.com/about/terms-of-use/
- Generated by `apps/web/scripts/split_admin1.py` (Python standard library only). The raw downloads
  are stored in `/tmp/td-natural-earth/` and are not part of the repository.
  - `countries.json`: properties `NAME`, `ADM0_A3`, `CONTINENT`; features with CONTINENT
    "Seven seas (open ocean)" removed.
  - `admin1/<ADM0_A3>.json`: one file per country, properties `name`, `adm0_a3`, `iso_3166_2`.
  - Files are keyed by `ADM0_A3`, not `ISO_A3`, because `ISO_A3` is `-99` for several countries.
  - Coordinates rounded to 3 decimals and simplified (Douglas-Peucker, 0.02° for countries,
    0.01° for regions).
  - `countries.json` only: parts (islands) smaller than 0.1 square degrees are dropped, except each
    country's largest part. This cuts the number of globe meshes (each part is its own mesh); the
    admin-1 files keep all parts for the 2D map.
- Known limit: admin-1 units differ by country (for example, France has 101 départements,
  including overseas départements).

## Earth image: NASA Blue Marble

- File: `blue-marble-2048x1024.jpg`, resized from `world.topo.bathy.200407.3x5400x2700.jpg`
  (Blue Marble Next Generation, topography and bathymetry, July 2004) with macOS `sips`.
- Page: https://science.nasa.gov/earth/earth-observatory/blue-marble-next-generation/base-topography-bathymetry/
  (former NASA Visible Earth page https://visibleearth.nasa.gov/images/73909, which now redirects there)
- File URL: https://assets.science.nasa.gov/content/dam/science/esd/eo/images/bmng/bmng-topography-bathymetry/july/world.topo.bathy.200407.3x5400x2700.jpg
- Credit: NASA Earth Observatory. Usage basis: NASA Images and Media Usage Guidelines,
  https://www.nasa.gov/nasa-brand-center/images-and-media/ . No NASA logo or insignia is used.

## Austrian districts and municipalities: geoBoundaries (not in this folder)

These boundaries are not stored as static files. The backend loads them from the geoBoundaries API
(release gbOpen, no API key) for `GET /api/v1/regions/{country_iso3}/{adm1_id}`
(`apps/api/src/trend_detective/providers/geoboundaries.py`, `services/regions.py`).

- License, as stated in the geoBoundaries metadata for all three levels: **Creative Commons
  Attribution-ShareAlike 2.0**. The simplified boundaries the backend returns are derived from this
  data and are under the same license.
- Attribution: "Boundaries: geoBoundaries (gbOpen), www.geoboundaries.org; source data: Federal
  Office for Metrology and Survey, Austria (BEV)".
- Levels used:
  - ADM1 (states, used to match the state), boundaryID `AUT-ADM1-97560089`,
    https://www.geoboundaries.org/api/current/gbOpen/AUT/ADM1/
  - ADM2 (districts), boundaryID `AUT-ADM2-14549572`,
    https://www.geoboundaries.org/api/current/gbOpen/AUT/ADM2/
  - ADM3 (municipalities), boundaryID `AUT-ADM3-71698017`,
    https://www.geoboundaries.org/api/current/gbOpen/AUT/ADM3/
- Year represented: 2017; geoBoundaries build date: 12 Dec 2023. Changes after 2017 are not
  included. Vienna is a single unit.
- Original source named in the metadata: Federal Office for Metrology and Survey, Austria (BEV),
  www.bev.gv.at

## US states and counties: geoBoundaries (not in this folder)

Like the Austrian data, these boundaries are loaded by the backend from the geoBoundaries API
(release gbOpen, TopoJSON) for `GET /api/v1/regions/{country_iso3}/{adm1_id}`.

- License, as stated in the geoBoundaries metadata for both levels: **Public Domain**
  (license source: www.census.gov/programs-surveys/geography/technical-documentation/naming-convention/cartographic-boundary-file.html).
- Attribution: "Boundaries: geoBoundaries (gbOpen), www.geoboundaries.org; source data: United
  States Census Bureau, MAF/TIGER Database".
- Levels used:
  - ADM1 (states, used to match the state), boundaryID `USA-ADM1-66186276`,
    https://www.geoboundaries.org/api/current/gbOpen/USA/ADM1/
  - ADM2 (counties and county equivalents such as parishes and boroughs), boundaryID
    `USA-ADM2-52423323`, https://www.geoboundaries.org/api/current/gbOpen/USA/ADM2/
  - geoBoundaries has no ADM3 for the USA, so there is no municipality level.
- Year represented: 2018; geoBoundaries build date: 12 Dec 2023. Connecticut still shows its
  8 former counties, not the planning regions the Census Bureau has used since 2022.
- Covered: the 50 states and DC. Puerto Rico and the other territories are not covered.
